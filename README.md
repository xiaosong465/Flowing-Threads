# 项目文档：流动话题公共问答社区（Markdown）

> 
> 项目名称：流问 —— 流动话题公共问答频道
> 目标用户：大学生、青年群体
> 项目定位：**话题持续流动的公共问答社区，区别于贴吧静态帖子，问题持续流转，多人讨论为核心**
> 技术方案：Web 网页项目（不做 App、不做桌面端，降低开发成本）

## 1. JTBD 用户任务分析

### Job To Be Done（核心任务）

> 
> 当年轻人想提出开放式问题，或者想浏览别人的问题、参与多人讨论时，**他想要进入一个话题持续流动的公共问答频道**，以便快速看到新鲜问题、参与多人讨论，并且优先看到高热度讨论内容；同时过滤掉自己不感兴趣的话题关键词。
> 
> 
> 当前替代方案：贴吧、知乎、论坛、QQ 群。
> 现有方案痛点：
> 
> 
> 1. 贴吧帖子一旦沉底基本不再活跃，帖子是静态的；
> 2. QQ 群消息刷屏，历史问题很难回溯，没有热度排序；
> 3. 普通问答平台（知乎）以单条问答为主，多人连续讨论不是核心；
> 4. 很难批量屏蔽一类关键词，不感兴趣内容持续出现。

#### 用户任务拆解

1. 提问：发布问题，自动进入【最新频道】流动池
2. 浏览：查看最新流动问题，或进入历史循环频道看存量热门问题
3. 互动：回答、评论、点赞；热度自动计算（点赞 + 评论数量）
4. 过滤：设置屏蔽关键词，包含该关键词的问题直接隐藏，不再展示

#### 成功衡量指标（多方验证指标）

- 提问发布到收到第一条回复的平均时间
- 用户单次访问浏览问题数量
- 屏蔽关键词功能使用率
- 热度高的问题持续讨论天数（对比贴吧，看话题存活时长）

## 2. 逆向思维 Pre-mortem 失败模式分析（逆向思维：预想项目上线后为什么会失败）

> 
> 核心假设：项目开发完成上线，但项目死掉，我们反向推导所有失败原因，提前规避。

### 2.1 需求层面失败

1. **起步冷启动灾难（项目最大风险，郑晓松原文提到：起步极难）**
> 
> 逆向猜想：刚上线，0 提问、0 回复。没有用户就没有话题，没有话题吸引不到新用户，直接卡死。
> 规避：MVP 阶段人工灌入一批初始问题 + 回答作为种子内容；**MVP 不追求公网开放，仅小范围（本班 / 同校学生内测）**。
2. **热度算法设计缺陷**
> 
> 逆向猜想：只简单统计点赞，灌水评论刷热度，低质量问题长期置顶，优质问题被淹没，用户流失。
> 规避：热度公式综合【评论数 + 点赞，加入时间衰减】，新问题有基础曝光权重，防止老问题永久霸占首页。
3. **话题流动逻辑用户看不懂**
> 
> 逆向猜想：用户不理解 “最新频道、历史频道” 的区别，不知道问题会流动循环，使用门槛高。
> 规避：简化概念，页面简短说明；MVP 弱化复杂循环逻辑，先验证基础问答 + 热度排序。

### 2.2 产品体验失败

1. **屏蔽关键词功能体验差**
> 
> 逆向猜想：关键词屏蔽只屏蔽标题，正文依旧能看到；屏蔽词过多导致几乎看不到任何内容。
> 规避：标题 + 正文同时匹配屏蔽词；支持随时开启 / 关闭屏蔽、删除屏蔽词。
2. **话题 “流动” 变成噱头，和普通论坛无差别**
> 
> 逆向猜想：功能做完，但本质还是静态帖子，没有实现 “流动话题” 的差异化，用户觉得和贴吧一样，没有独特价值。
> 规避：MVP 核心差异化只保留两点：双频道（最新 / 历史）、热度动态重排；不额外堆砌功能。

### 2.3 技术层面失败

1. **功能爆炸**：小组额外增加收藏、私信、头像、通知等非核心功能，开发工作量暴涨，项目延期烂尾。
> 
> 规避：制定**不做清单**：MVP 不做私信、个人主页、消息通知、上传图片。
2. **数据库性能问题**：问题、评论数量增加后，热度实时重排查询缓慢，页面加载卡顿。
> 
> 规避：MVP 使用 SQLite，数据量小，不做复杂实时计算；热度定时后台计算，不每次打开页面实时全量统计。

### 2.4 用户习惯层面失败

> 
> 逆向猜想：用户习惯知乎 / 贴吧，不愿意迁移到新平台，不愿意在新社区提问回复。
> 规避：小范围熟人圈子内测，降低迁移成本；核心卖点强调：**多人流动讨论，话题不会快速死掉**。

> 
> 核心逆向结论：这个项目最大的敌人不是代码，是**冷启动（没人、没内容）**，其次是 “做一堆附加功能，丢失核心特色”。

## 3. MVP 最小快速原型（最小可行产品）

> 
> 原则：只保留最核心差异化能力，砍掉所有非必要功能，快速验证想法：**流动双频道问答、热度排序、关键词屏蔽**
> 技术选型推荐：`FastAPI + Vue3 + Element Plus`（Web 网页，小组 Python 技术栈适配）

### ✅ MVP 包含功能（只做下面这些）

1. 用户基础
   - 简易匿名提问、匿名回复（**不需要注册登录！** 大幅降低门槛，MVP 不做账号系统）
2. 双频道【最新频道】【历史频道】
   - 最新频道：展示新提交的问题，按发布时间倒序
   - 历史频道：存量问题，**按热度（点赞 + 评论）排序置顶**
3. 互动能力
   - 对问题点赞；对问题发表评论回答
   - 热度自动计算：热度 = 点赞数 + 评论数；后台定时更新热度
4. 关键词屏蔽（核心特异化功能）
   - 输入关键词添加到屏蔽列表；包含屏蔽词的问题，页面直接隐藏
5. 问题详情页：查看问题 + 全部评论讨论

### ❌ MVP【不做清单】（严禁开发，防止功能爆炸）

- 不做用户注册、账号、密码、头像、个人主页
- 不做私信、消息通知、邮件 / 闹钟提醒
- 不做图片上传、富文本编辑器，只支持纯文本
- 不做复杂权限、审核系统
- 不做移动端原生 App、Windows 客户端；仅 Web 网页
- 不做复杂 AI 总结、RAG 知识库（后续迭代版本再加）

### MVP 页面结构

1. 首页：切换【最新频道】/【历史频道】
2. 提问弹窗：输入标题 + 问题正文提交
3. 问题详情页：展示问题、所有评论，点赞按钮
4. 侧边栏：屏蔽关键词管理面板（添加、删除屏蔽词）

### MVP 验证方式（多方验证）

1. 小范围测试：邀请 20~30 名大学生内测 2 周
2. 观测指标：提问数量、回复数量、屏蔽词使用情况
3. 用户访谈：询问用户，是否感受到话题是 “流动” 的，对比贴吧使用感受
4. 可用性测试：观察用户完成提问、回复、添加屏蔽词的操作流程

## 4. 项目核心差异化总结（用于报告）

普通贴吧：帖子一旦下沉就不再曝光 → **帖子是静态的**
本项目：问题分为最新池和历史热度池，优质讨论持续留在历史频道获得曝光，话题持续流转，多人讨论是产品核心 → **话题是活的**

## 5. 后续迭代路线（MVP 验证成功之后，再加）

1. 版本 2：增加 AI 辅助回答、知识库沉淀（类似百度知道）
2. 版本 3：简单用户账号、收藏功能
3. 版本 4：通知提醒功能
